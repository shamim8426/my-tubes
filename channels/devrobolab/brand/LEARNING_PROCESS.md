# How DevRoboLab learns from other channels and stays UNIQUE (user rule 2026-11-04)

Goal: keep learning new editing styles, ways of presenting and motion/symbol ideas from good channels, record every learning permanently in git, and use it to make OUR OWN videos, never copies.

1. WHEN: the user gives a link and says to learn from it ('isse seekho'), or a study is part of a plan. Follow shared/RULES.md section 12c (it wins on any conflict): tools/yt-dlp.exe, no login, no cookies, only into the git-ignored study/ folder (never committed), at most ~6 videos, <= 720p.
2. ANALYSE (frames + scene-cut rate + faster-whisper transcript kept only inside study/): text (size % of frame, words per reveal, reveal/entry motion), motion/edit (cut rhythm, transitions, zooms, callouts, moving elements per beat), structure (hook timing, beats, ending), sound (music level, SFX, voice speed), what makes it clear. Write NUMBERS and principles in our own words.
3. RECORD PERMANENTLY BEFORE DELETING: (a) brand/STYLE_LEARNINGS.md (abstract + numeric, with a 'Map to DevRoboLab' section: what the engine already supports, what is missing, ranked by impact/effort); (b) research/study_log.md (date, channel link, videos studied with titles/links, 3-line summary, Status); (c) commit + push (tools\sync.ps1) and CHECK git shows the files; (d) only then delete study/<channel>/ and set the log Status to 'deleted'. Nothing from the download (frame, clip, audio, music, voice, script/narration, exact title/thumbnail, characters, channel name outside study_log.md) is ever reused.
4. TURN LEARNINGS INTO OUR OWN STYLE: build the missing engine pieces opt-in (templates/deck_template.html, scripts/build_deck.py), prove old decks render unchanged (pixel-diff of stills), make a REFERENCE SHEET of real stills first and show it to the user, then the video. Put every new engine field and rule in STYLE_GUIDE.md (v4+ sections) and add a line to the Enhancements log.
5. UNIQUENESS CHECK for every new video: does it look recognisably DevRoboLab (white/black/yellow marker, robot, draw strokes) and NOT like the studied channel? Do not reproduce another channel's combination (background colour + type + hero device + card pattern + ending). Say in the report what is ours.
6. MEMORY: after each study or style decision also update the user's memory repo (shamim8426/claude-memory, topics/devrobolab.md + INDEX.md) so any session (PC or cloud) starts with the same knowledge.
